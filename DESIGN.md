# Архитектурный дизайн и анализ сложности (Bulls and Cows)

Данный документ описывает архитектурные решения, структуры данных, алгоритмы ядра, оценку вычислительной сложности (Big O) и применённые принципы чистого кода (Clean Code) в проекте «Быки и коровы».

---

## 1. Структуры данных и состояние игры

### 1.1 Состояние игры (`GameState`)

Игровое состояние описано строгим иммутабельным интерфейсом TypeScript (`src/core/types.ts`):

```ts
interface GameState {
  readonly settings: GameSettings;
  readonly secret: string;
  readonly status: GameStatus; // 'idle' | 'playing' | 'won'
  readonly history: readonly HistoryEntry[];
  readonly startTimeMs: number;
  readonly endTimeMs: number | null;
}
```

#### Почему выбраны такие структуры:

- **Иммутабельность**: Любое изменение состояния порождает новый объект через спред-оператор (`{ ...state, history: [...state.history, newEntry] }`), старый объект не мутирует. Это гарантирует отсутствие непредсказуемых побочных эффектов, упрощает отладку и делает переходы состояния прозрачными и детерминированными для тестов.
- **Секрет и попытки в виде строк**: Хранятся как строки в нижнем регистре. Это позволяет без костылей и дополнительных преобразований сохранять лидирующие нули (например, `'0123'`), а также одинаково обрабатывать цифры шестнадцатеричной системы счисления (`'0'`–`'f'`).
- **Массив истории (`readonly HistoryEntry[]`)**: Защита от задвоения попыток реализована через чистый предикат `Array.prototype.some`. Так как число ходов в раунде редко превышает 15–20, линейный обход массива даёт минимальный оверхед по памяти без необходимости поддерживать отдельную синхронизацию с `Set`.

### 1.2 Хранение рекордов (`LeaderboardEntry[]`)

- Данные сериализуются в формат JSON и сохраняются в `localStorage`.
- Логика ранжирования и фильтрации вынесена в чистые функции (`compareRecords`, `addRecord`, `loadRecords`, `saveRecords` в `src/storage/leaderboard.ts`), не зависящие от браузерного окружения и полностью покрытые модульными тестами с мок-хранилищем.

## 2. Алгоритмы ядра

### 2.1 Алгоритм `evaluateGuess(secret, guess)` (`src/core/game.ts`)

- **Задача**: Подсчитать число быков (цифра угадана и стоит на своём месте) и коров (цифра есть в числе, но стоит на другой позиции).
- **Функциональная реализация**: Выполнена без ручных циклов со счётчиками (`for`, `while`) исключительно методами массивов:
  1. Обе строки приводятся к нижнему регистру (`toLowerCase`).
  2. Строка попытки разбивается на массив символов: `[...normalizedGuess]`.
  3. **Быки (`bulls`)**: Фильтрация элементов, у которых символ совпадает с символом секрета по тому же индексу: `char === normalizedSecret[index]`.
  4. **Коровы (`cows`)**: Фильтрация элементов, которые стоят не на своём месте, но содержатся в секрете: `char !== normalizedSecret[index] && normalizedSecret.includes(char)`.
  5. Возвращается замороженный объект `{ bulls, cows }`.

### 2.2 Алгоритм `countPossibleSecrets(length, base)` (`src/core/math.ts`)

- **Задача**: Вычислить количество возможных вариантов секрета длины $length$ в системе счисления $base$ (число размещений без повторений):
  $$P(base, length) = \frac{base!}{(base - length)!} = base \times (base - 1) \times \dots \times (base - length + 1)$$
- **Рекуррентное соотношение**:
  - Базовый случай: при `length === 0` возвращается `1` (пустая комбинация ровно одна).
  - Краевые условия: при `length < 0` или `length > base` возвращается `0`.
  - Рекурсивный шаг: `base * countPossibleSecrets(length - 1, base - 1)`.
- **Мемоизация**: Обернута в собственную generic-функцию `memoize` (`src/core/memoize.ts`) на базе структуры `Map`. Повторные вызовы с одинаковыми параметрами возвращают кэшированный результат за $O(1)$ без повторного спуска по стеку рекурсии.

## 3. Анализ вычислительной сложности (Big O)

Обозначения:

- $L$ — длина секретного числа (`length`, где $2 \le L \le 6$).
- $B$ — основание системы счисления (`base`, где $B \in \{2, 8, 10, 16\}$).

| Функция                        | Временная сложность (Time)               | Пространственная сложность (Space) | Обоснование                                                                                                                                                                                                                                                                                                                               |
| :----------------------------- | :--------------------------------------- | :--------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSecret(L, B)`         | $O(L \cdot B)$                           | $O(B)$                             | Создаётся алфавит длины $B$. Выполняется ровно $L$ рекурсивных шагов выборки. На каждом шаге метод `.filter()` обходит оставшийся алфавит размером не более $B$. Глубина стека вызовов — $L$, затраты памяти определяются хранением среза алфавита размера $B$.                                                                           |
| `evaluateGuess(secret, guess)` | $O(L^2)$                                 | $O(L)$                             | Строка разбивается в массив длины $L$. Быки считаются за один проход по массиву $O(L)$. Коровы считаются через проверку вхождения `.includes()`, которая для каждого из $L$ символов делает поиск по строке длины $L$, давая $O(L \cdot L) = O(L^2)$. При максимальном $L = 6$ это не более 36 элементарных операций (доли микросекунды). |
| `isValidGuess(guess, L, B)`    | $O(L)$                                   | $O(L + B)$                         | Проверка длины выполняется за $O(1)$. Срез допустимого алфавита занимает $O(B)$. Проверка каждого символа через предикат `.every()` требует $O(L)$. Создание `new Set` для проверки уникальности занимает $O(L)$ времени и памяти. Итоговая сложность — $O(L + B) = O(L)$.                                                                |
| `countPossibleSecrets(L, B)`   | $O(1)$ (из кэша) / $O(L)$ (первый вызов) | $O(L)$                             | Без мемоизации глубина рекурсии равна $L$ с одним умножением на каждом шаге $\to O(L)$. Благодаря `memoize` все повторные вызовы извлекаются из хеш-таблицы `Map` за константное время $O(1)$.                                                                                                                                            |

## 4. Принципы чистого кода (Clean Code)

1. **Чистые функции и отсутствие побочных эффектов (Pure Functions)**:
   - _Где применено_: `src/core/validator.ts`, `src/core/secret.ts`, `src/core/game.ts`, `src/core/math.ts`.
   - Функции ядра не читают и не меняют глобальное состояние, не обращаются к DOM или `window`. Генератор случайных чисел `random` передан через инжекцию зависимостей (`random: RandomGenerator = Math.random`), что делает функцию детерминированной и полностью тестируемой.

2. **Принцип единственной ответственности (Single Responsibility Principle — SRP)**:
   - _Где применено_:
     - `validator.ts` — только валидация символов и строк.
     - `math.ts` — комбинаторные вычисления и мемоизация.
     - `secret.ts` — генерация секрета.
     - `game.ts` — подсчёт быков/коров и редюсер состояния раунда.
     - `leaderboard.ts` — адаптер сохранения и сортировки рекордов.
     - `dom.ts` — безопасное создание элементов DOM.

3. **Каррирование и функции высшего порядка (Currying & HOF)**:
   - _Где применено_: `createDigitValidator(base)` в `src/core/validator.ts`.
   - Фабрика фиксирует основание системы счисления один раз и возвращает предикат `(char: string) => boolean`. Функция используется сразу в двух местах приложения: для валидации всей строки в `isValidGuess` и для блокировки недопустимых символов на лету в обработчиках ввода `beforeinput` / `input`.

4. **Быстрый отказ (Fail-Fast)**:
   - _Где применено_: `generateSecret` в `src/core/secret.ts` и `countPossibleSecrets` в `src/core/math.ts`.
   - Функции мгновенно проверяют граничные условия и выбрасывают понятный `RangeError`, если запрошенная длина превышает алфавит уникальных цифр или меньше нуля, не допуская некорректного выполнения.

5. **Безопасность и отказ от небезопасных методов (No innerHTML)**:
   - _Где применено_: `src/ui/dom.ts`, `src/ui/app.ts`.
   - Полный отказ от `innerHTML` и `insertAdjacentHTML`. Все узлы интерфейса генерируются через фабрику `createElement`, текстовый контент монтируется исключительно через безопасный `textContent`.
